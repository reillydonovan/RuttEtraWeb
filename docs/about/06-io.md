## I/O

External integration. The synth speaks every protocol that fits in a browser, plus some that don't (via bridges).

### MIDI

- **Browser support** — Web MIDI is available in Chrome and Edge. Safari does not implement it; if you need MIDI in Safari, use a CV-to-MIDI bridge over OSC (see below) or run the synth in Chrome/Edge.
- **Devices** — pick input + output devices from the I/O → MIDI panel. Multiple inputs can be active at once; the active output receives outbound CCs.
- **MIDI Learn** — click any modulation Source dropdown, choose `MIDI CC`, expand the row, and click **Learn**. Wiggle the knob on your controller. The first CC seen binds.
- **14-bit CC** — Settings panel toggle. When enabled, MIDI Learn pairs the bound CC with `CC + 32` (LSB) automatically. Resolves the 7-bit step problem on smooth params.
- **MIDI Clock sync** — top of the Modulation panel: BPM source = `MIDI`. Divisions: 1/1, 1/2, 1/4, 1/4D, 1/8, 1/8T, 1/16, 1/32. The "no clock" indicator lights when sync is requested but no clock has arrived in the last 2 seconds.
- **Note input** — `MIDI Note` source emits `note number`, `velocity`, `gate`. `Key Follow` mode emits 1V/oct-style scaled output (useful for driving Z Push pitch-style). `Last note` vs `poly average` mode picks how chords collapse to a single value.
- **MIDI Out** — toggle in the I/O → MIDI panel. Each modulation slot's live value is sent as a CC every frame on the channel/CC pair you assign. The synth becomes a MIDI source for your DAW.

### Audio

- **Sources** — microphone, audio file (drag-drop), tab audio (Chrome only). System audio capture requires a virtual loopback driver (BlackHole on macOS, VoiceMeeter on Windows).
- **Multi-channel** — Chrome 90+ exposes all channels of the picked device for selection by the FFT analyzer and the CV-input subsystem. Firefox limits to two channels.
- **FFT analyzer** — FFT size, band count, spacing (linear / log / mel), smoothing. Each band is a modulation source (`Audio Band [n]`).
- **Spectrum-as-texture** — toggle in I/O → Audio. The current FFT magnitude is mapped onto a 1D texture and applied per-row to the scanline mesh. With this on, every scanline reads its own frequency bin, and the geometry literally becomes audio.
- **Beat detection** — sensitivity slider (`audioBeatSensitivity`). The `Beat` modulation source fires a 1-frame impulse on each detected onset.
- **Monitor** — toggle to route the analysis input back to the speakers. Usually OFF — feedback is the default outcome with a mic input.

### CV input

External control voltages, brought in through one of four routes:

- **DC-coupled audio interface (best)** — Expert Sleepers ES-3 / ES-5 / ES-8 / ES-9, MOTU UltraLite, some Focusrite Clarett. Audio inputs receive raw voltage; pick the device under I/O → Audio, and CV channels become source candidates in `CV Input` modulation rows.
- **CV-to-MIDI converter** — devices like the Endorphin.es Shuttle Control or the Befaco CV Thing translate voltages to MIDI CC. Lower resolution (7- or 14-bit) but works in Safari and over USB on any audio interface.
- **OSC bridge** — point a hardware ADC at a microcontroller (Arduino, Teensy, Raspberry Pi) running the bridge in `tools/osc-bridge/`. Send `/cv/0`, `/cv/1`, ... messages over WebSocket to the synth.
- **Gamepad / HID** — every connected gamepad axis and button is a CV source. Use a controller with continuous analog axes (PS / Xbox sticks, racing wheels) for proper "physical knob" control.

#### Voltage handling

- **Ranges** — `±5V`, `0–5V`, `±10V`. Set per-channel.
- **Polarity** — flip without touching wiring.
- **Smoothing** — single-pole low-pass in ms; useful when the source is jittery.
- **Calibration (DC offset)** — patch `0V` to the input, click **Calibrate Zero**. The current input value is stored and subtracted from all future readings.
- **CV Learn** — same pattern as MIDI Learn. Click Learn, wiggle the source, the synth picks the first non-noise channel.

#### Limitation: AC-coupled interfaces

Most consumer audio interfaces are AC-coupled, meaning they high-pass-filter the signal at ~10 Hz. A steady DC voltage drifts toward zero within seconds. AC-coupled inputs can still detect transients and oscillating CVs (LFO, audio-rate) but cannot read constant or slow-moving voltages. The DCU panel's CV Input section warns when the active interface is suspected AC-coupled.

### CV output

The browser sends voltages OUT to external hardware through DC-coupled audio outputs.

- **Hardware requirement** — same as input. A DC-coupled audio interface is required. The synth uses a separate `AudioContext` targeting the chosen output device via `setSinkId`, so CV outputs are physically isolated from any audible audio routed to your normal monitoring path.
- **Output types per channel** — `cv` (continuous), `gate` (boolean threshold), `trigger` (pulse on rising edge), `clock` (square at tempo division), `pitch` (1V/octave converted from MIDI note number).
- **1V/octave pitch** — calibration UI in the CV Output section. Reference note (default `C2 = 0V`), V/oct scaling (default `1.000`), glide ms, optional quantize-to-scale. The Calibrate Pitch panel plays C2 / C6 alternately so you can match a tuner.
- **Output isolation** — CV channels live on their own `AudioContext`. They can never enter the main audio mix.
- **Startup ramp** — every channel ramps from 0V to its current target over 100ms when enabled. On disable, it ramps back to 0V. No DC click into your modular. CV channels load their configurations but stay disabled until you re-enable them per channel after every page load and every project open. (See Design Principles — [*The synth doesn't make sound by accident*](#no-accident-sound).)
- **Clamping** — every sample is hard-clamped to ±10V before reaching the worklet output. Even a runaway modulation can't blow your modules up.
- **Latency** — typical end-to-end latency from a parameter change in the browser to a voltage change at the patch tip is **20–50 ms**, dominated by the audio output buffer. The synth is unsuitable as a sample-accurate VCA driver, but excellent as a continuous-CV / slow-modulation peer in a modular rig.
- **Test buttons** — each channel has a **Test** button that holds the output at +2.5V for as long as you press it. Use to verify wiring before patching for real.

### Sonification (audible voice)

The synth's first audible-output feature: a single audio voice whose parameters are driven by statistics computed from the scanline mesh. Faithful to the 1970s practice (Steina Vasulka, Bill Hearn) of routing video signals through audio amplifiers to literally hear the image. Bright = loud, motion = filter motion, vertical position of brightness = pitch.

- **Voice chain** — `OscillatorNode → BiquadFilterNode → GainNode (amp) → GainNode (master) → DynamicsCompressorNode (limiter) → AudioContext.destination`. A parallel `MediaStreamAudioDestinationNode` taps the post-master / post-limiter signal so recordings and broadcasts include sonification audio without affecting the main speaker output.
- **Mesh statistics (8 of them)** — computed each frame from the same `VideoTap` readback the `video-*` graph nodes use, with the DCU brightness pipeline (luma → threshold → contrast → gamma) mirrored on the CPU side so the sonified signal tracks what's visible on screen, not just raw video luma:
    - `meanBrightness` — average post-DCU luminance across the analysis grid.
    - `brightnessVariance` — spread of per-row brightness; high = strong contrast.
    - `verticalCentroid` — Y position of brightness center-of-mass (0 = top, 1 = bottom).
    - `horizontalCentroid` — X position of brightness center-of-mass (0 = left, 1 = right).
    - `meshActivity` — frame-to-frame change magnitude over the per-row buffer (motion estimate).
    - `peakRow` — Y position of the brightest scanline.
    - `peakBrightness` — brightness value at that row.
    - `edgeDensity` — fraction of rows whose row-to-row brightness delta exceeds 10%.
- **Mapping layer** — four voice parameters (Pitch, Amplitude, Cutoff, Resonance), each assigned to one of the eight stats with an easing curve (Linear, Exponential, Logarithmic, S-Curve / smoothstep). A single Smoothing slider applies a 1-pole lowpass to all four mappings (default 40 ms; 5 ms = twitchy, 200 ms = drone-smooth). Pitch additionally has a configurable MIDI-note range (default C2..C6) and a Quantize toggle (off = continuous theremin glide).
- **Default mapping** — Pitch ← `verticalCentroid` (Exponential), Amplitude ← `meanBrightness` (Linear), Cutoff ← `brightnessVariance` (Exponential), Resonance ← `meshActivity` (Linear). Tuned to feel musical with arbitrary video.
- **Performance** — 64-row analysis grid (matches the lo-res VideoTap), <0.1 ms per frame on mid-tier laptops. The voice itself is standard Web Audio cost.

#### Safety surface ("first audio output")

This is the synth's first audible output, so the safety surface is intentionally heavy. (See Design Principles — [*The synth doesn't make sound by accident*](#no-accident-sound).)

- **Default disabled** — every page load, every preset import. The settings migration explicitly forces `sonification.enabled = false` regardless of the saved value (mirrors the CV-output "channels start disabled" rule). The synth makes no sound until a user explicitly clicks **Enable**.
- **-18 dB default volume** — quiet by design.
- **500 ms soft-start ramp** — master gain rises from -∞ to the user's configured level over 500 ms on enable. No clicks; no surprises if a previous session left master high.
- **Brick-wall limiter** — `DynamicsCompressorNode` with -3 dBFS threshold, ratio 20, 6 dB knee, attack 3 ms, release 100 ms sits between master gain and destination. Resonant filter sweeps cannot produce above-unity output.
- **Mic-feedback gate** — when the audio envelope follower (FFT analyser) is running with mic input AND sonification is enabled, master gain is auto-forced to 0 with a UI banner explaining why. The synth refuses to ship a feedback loop; the user has to disable mic-as-envelope-source to enable both at once safely.
- **Browser autoplay policy** — the Enable click is the natural user gesture for the AudioContext to actually run. If the toggle is flipped some other way (URL config, preset import — should be impossible thanks to the migration's force-off), a "click anywhere on the canvas to start audio" banner appears, and the next canvas click resumes the context.
- **Routing isolation** — Sonification owns its own `AudioContext` (separate from CV Output's, which targets a DC-coupled interface via `setSinkId`). The two surfaces share no mixer node; sonification audio can never leak into a CV channel and vice versa.

#### Recording / broadcast capture

When sonification is enabled and recording / broadcasting is active:

- The recorder pulls `getCaptureStream()` from the `Sonification` instance and adds its audio track(s) to the canvas `MediaStream` it hands to `MediaRecorder`. Combined with mic-on-record, both sources are mixed by the browser at recording time.
- Same for the broadcaster: tracks are added to the PeerJS call's stream, so viewers hear the sonification voice synchronized with the visual.
- Capture taps post-master / post-limiter, so the recorded audio is identical to what the user hears (limiter included).

### OSC

- **Bridge required** — browsers can't speak OSC directly. The reference bridge in `tools/osc-bridge/` runs as a small Node WebSocket server, translates `/path value` messages to and from OSC, and the synth connects to it at `ws://localhost:8765` by default.
- **Bidirectional Learn** — OSC mappings work in both directions: a learn pattern catches incoming OSC; outgoing OSC sends mod values to your hardware on configurable paths.
- **TouchOSC layout** — the I/O → OSC panel can export a TouchOSC layout matching the current modulation matrix. Open it in TouchOSC Editor to fine-tune visuals.

### Video sources {#video-sources}

The **Source** panel manages the video signal that feeds the scanline mesh. Four modes coexist without replacing each other (see Design Principles — [*Coexistence over replacement*](#coexistence)): switching sources leaves all synthesizer settings intact.

#### Webcam

Pick a device from the dropdown. Resolution and FPS are set in the **Capture Settings** sub-group. "Auto" lets the camera pick its native resolution; explicit presets (480p → 4K) request a specific size. The browser negotiates the closest match the hardware supports. Changes take effect on the next "Use Webcam" click — mid-session resolution changes are intentionally explicit (see [*Explicit user action*](#explicit-action)).

Virtual cameras created by OBS, NDI Virtual Input, or Syphon Virtual Camera appear in the device list alongside physical cameras — no special configuration needed.

#### Screen capture

Captures a browser tab, application window, or full display as the video source. Useful for projecting live content from another application, routing browser-tab content through the synth, or capturing a canvas from software running in the same browser.

#### Video file

Drag-drop or pick a local video file. Plays in a loop. File is read directly in-browser; it is never uploaded to any server.

#### Stream URL {#stream-url}

Connects to a remote video stream at a URL you paste. Supported formats:

| Format | Extension | How it works |
|--------|-----------|--------------|
| HLS    | `.m3u8`   | Native on Safari. Chrome / Firefox / Edge load hls.js on demand. |
| Direct video | `.mp4`, `.webm` | Any URL the browser can play as a `<video>`. |
| MPEG-DASH | `.mpd` | **Not supported** — re-mux to HLS using ffmpeg. |

The URL is remembered across sessions but not auto-connected on load — reconnect requires an explicit click. Errors (bad URL, missing CORS header, unsupported format) are shown inline with no silent fallback.

**Connecting professional video software** — most stage/VJ applications (Millumin, Resolume, TouchDesigner, etc.) can't send video directly to a browser. Practical bridge paths:

- **OBS virtual camera** — set OBS as a Scene or Virtual Camera output from the application, then pick it under Webcam. Works on macOS and Windows with no extra tools.
- **NDI** — install NDI Tools (free from ndi.tv). Applications with NDI output appear as system webcams via NDI Virtual Input.
- **Syphon → virtual camera (macOS)** — Syphon-outputting apps feed *Syphon Virtual Camera*, which appears in the webcam list in Chrome.
- **HLS relay** — if the application outputs RTMP/RTSP, convert to HLS with MediaMTX or ffmpeg and paste the `.m3u8` URL into Stream URL.

**RTSP / IP cameras** — browsers can't connect to RTSP directly. Run a relay (MediaMTX, ffmpeg → HLS) and paste the `.m3u8` URL.

**CORS** — the stream server must allow cross-origin requests (`Access-Control-Allow-Origin: *`). Streams that block CORS fail with a visible error. A self-run relay that adds the header is the standard workaround.

**Latency** — HLS buffering adds 2–10 s. For near-zero latency, use Screen Capture (browser tab from another application) or a WebRTC relay.

### Live output — WHIP and P2P broadcast {#live-output}

The synth can push its canvas as a live stream to external software and CDNs, not just receive.

#### WHIP output (Share → WHIP Output) {#whip-output}

WHIP (WebRTC HTTP Ingestion Protocol) is the send-side counterpart to HLS input. The synth sends an SDP offer to a WHIP server (one HTTP POST), which re-distributes the canvas as HLS, RTMP, RTSP, or WebRTC — whatever the server supports.

| Server | Endpoint | Notes |
|--------|----------|-------|
| OBS 30+ | `http://localhost:8080/whip` | Tools → WHIP Server → Start. No token. |
| MediaMTX | `http://localhost:8889/whip/<name>` | Free, self-hosted. Outputs HLS, RTMP, RTSP, WebRTC simultaneously from the same path. |
| Cloudflare Stream | From dashboard | Cloud CDN delivery; requires Bearer API token. |
| LiveKit Cloud | From dashboard | WebRTC room + HLS output; requires Bearer token. |

**Bearer token** — cloud services require an API token in the Token field. It is stored locally in your browser and never exported to preset files.

**OBS workflow** — OBS 30+ has a built-in WHIP server. Enable it under Tools → WHIP Server → Start. Paste the endpoint URL into Share → WHIP Output and click Start WHIP. OBS receives the canvas as a WebRTC track and can re-stream it to Twitch, YouTube, or record locally — with full OBS compositing on top.

**MediaMTX workflow** — MediaMTX is a free single-binary relay. Run it with defaults, set the WHIP endpoint to `http://localhost:8889/whip/synth`, and MediaMTX makes the stream available simultaneously as HLS (for the stream URL input of another synth instance), RTMP (for OBS), RTSP (for cameras and recording tools), and a built-in WebRTC web player.

#### P2P broadcast (Share → P2P Broadcast)

The synth generates a random peer ID and a shareable URL. Any viewer who opens that URL sees the live canvas streamed directly from the synth browser tab — no server, no account. The connection uses the public PeerJS signaling broker; both parties need to reach `peerjs.com`. Use this for quick sharing; use WHIP for production tools and CDN delivery.

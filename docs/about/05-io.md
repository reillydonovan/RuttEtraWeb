## I/O

External integration. The synth speaks every protocol that fits in a browser, plus some that don't (via bridges).

### MIDI

- **Browser support** — Web MIDI is available in Chrome and Edge. Safari does not implement it; if you need MIDI in Safari, use a CV-to-MIDI bridge over OSC (see below) or run the synth in Chrome/Edge.
- **Devices** — pick input + output devices from the I/O → MIDI panel. Multiple inputs can be active at once; the active output receives outbound CCs.
- **MIDI Learn** — click any modulation Source dropdown, choose `MIDI CC`, expand the row, and click **Learn**. Wiggle the knob on your controller. The first CC seen binds.
- **14-bit CC** — Settings panel toggle. When enabled, MIDI Learn pairs the bound CC with `CC + 32` (LSB) automatically. Resolves the 7-bit step problem on smooth params.
- **MIDI Clock sync** — top of the Modulation panel: BPM source = `MIDI`. Divisions: 1/1, 1/2, 1/4, 1/4D, 1/8, 1/8T, 1/16, 1/32. The "no clock" indicator lights when sync is requested but no clock has arrived in the last 2 seconds.
- **Note input** — `MIDI Note` source emits `note number`, `velocity`, `gate`. `Key Follow` mode emits 1V/oct-style scaled output (useful for driving Z Push pitch-style). `Last note` vs `poly average` mode picks how chords collapse to a single value.
- **MIDI Out** — toggle in the I/O → MIDI panel. Each modulation slot's live value is sent as a CC every frame on the channel/CC pair you assign. The synth becomes a MIDI source for your DAW.

### Audio

- **Sources** — microphone, audio file (drag-drop), tab audio (Chrome only). System audio capture requires a virtual loopback driver (BlackHole on macOS, VoiceMeeter on Windows).
- **Multi-channel** — Chrome 90+ exposes all channels of the picked device for selection by the FFT analyzer and the CV-input subsystem. Firefox limits to two channels.
- **FFT analyzer** — FFT size, band count, spacing (linear / log / mel), smoothing. Each band is a modulation source (`Audio Band [n]`).
- **Spectrum-as-texture** — toggle in I/O → Audio. The current FFT magnitude is mapped onto a 1D texture and applied per-row to the scanline mesh. With this on, every scanline reads its own frequency bin, and the geometry literally becomes audio.
- **Beat detection** — sensitivity slider (`audioBeatSensitivity`). The `Beat` modulation source fires a 1-frame impulse on each detected onset.
- **Monitor** — toggle to route the analysis input back to the speakers. Usually OFF — feedback is the default outcome with a mic input.

### CV input

External control voltages, brought in through one of four routes:

- **DC-coupled audio interface (best)** — Expert Sleepers ES-3 / ES-5 / ES-8 / ES-9, MOTU UltraLite, some Focusrite Clarett. Audio inputs receive raw voltage; pick the device under I/O → Audio, and CV channels become source candidates in `CV Input` modulation rows.
- **CV-to-MIDI converter** — devices like the Endorphin.es Shuttle Control or the Befaco CV Thing translate voltages to MIDI CC. Lower resolution (7- or 14-bit) but works in Safari and over USB on any audio interface.
- **OSC bridge** — point a hardware ADC at a microcontroller (Arduino, Teensy, Raspberry Pi) running the bridge in `tools/osc-bridge/`. Send `/cv/0`, `/cv/1`, ... messages over WebSocket to the synth.
- **Gamepad / HID** — every connected gamepad axis and button is a CV source. Use a controller with continuous analog axes (PS / Xbox sticks, racing wheels) for proper "physical knob" control.

#### Voltage handling

- **Ranges** — `±5V`, `0–5V`, `±10V`. Set per-channel.
- **Polarity** — flip without touching wiring.
- **Smoothing** — single-pole low-pass in ms; useful when the source is jittery.
- **Calibration (DC offset)** — patch `0V` to the input, click **Calibrate Zero**. The current input value is stored and subtracted from all future readings.
- **CV Learn** — same pattern as MIDI Learn. Click Learn, wiggle the source, the synth picks the first non-noise channel.

#### Limitation: AC-coupled interfaces

Most consumer audio interfaces are AC-coupled, meaning they high-pass-filter the signal at ~10 Hz. A steady DC voltage drifts toward zero within seconds. AC-coupled inputs can still detect transients and oscillating CVs (LFO, audio-rate) but cannot read constant or slow-moving voltages. The DCU panel's CV Input section warns when the active interface is suspected AC-coupled.

### CV output

The browser sends voltages OUT to external hardware through DC-coupled audio outputs.

- **Hardware requirement** — same as input. A DC-coupled audio interface is required. The synth uses a separate `AudioContext` targeting the chosen output device via `setSinkId`, so CV outputs are physically isolated from any audible audio routed to your normal monitoring path.
- **Output types per channel** — `cv` (continuous), `gate` (boolean threshold), `trigger` (pulse on rising edge), `clock` (square at tempo division), `pitch` (1V/octave converted from MIDI note number).
- **1V/octave pitch** — calibration UI in the CV Output section. Reference note (default `C2 = 0V`), V/oct scaling (default `1.000`), glide ms, optional quantize-to-scale. The Calibrate Pitch panel plays C2 / C6 alternately so you can match a tuner.
- **Output isolation** — CV channels live on their own `AudioContext`. They can never enter the main audio mix.
- **Startup ramp** — every channel ramps from 0V to its current target over 100ms when enabled. On disable, it ramps back to 0V. No DC click into your modular.
- **Clamping** — every sample is hard-clamped to ±10V before reaching the worklet output. Even a runaway modulation can't blow your modules up.
- **Latency** — typical end-to-end latency from a parameter change in the browser to a voltage change at the patch tip is **20–50 ms**, dominated by the audio output buffer. The synth is unsuitable as a sample-accurate VCA driver, but excellent as a continuous-CV / slow-modulation peer in a modular rig.
- **Test buttons** — each channel has a **Test** button that holds the output at +2.5V for as long as you press it. Use to verify wiring before patching for real.

### OSC

- **Bridge required** — browsers can't speak OSC directly. The reference bridge in `tools/osc-bridge/` runs as a small Node WebSocket server, translates `/path value` messages to and from OSC, and the synth connects to it at `ws://localhost:8765` by default.
- **Bidirectional Learn** — OSC mappings work in both directions: a learn pattern catches incoming OSC; outgoing OSC sends mod values to your hardware on configurable paths.
- **TouchOSC layout** — the I/O → OSC panel can export a TouchOSC layout matching the current modulation matrix. Open it in TouchOSC Editor to fine-tune visuals.

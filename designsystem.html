Modern · the default theme

One instrument, one language.

Rutt/Etra Web is a video synthesizer you play with a mouse, a MIDI controller and patch cables. Its interface follows a small set of rules, applied everywhere: three surface tiers, four type sizes, one spacing grid, and a single accent colour that only ever means state. This page is the reference: every token and every control, with its states.

Green is state, not decoration

Hover, selected, plugged, live: green. Everything else is neutral grey, so the one lit thing on screen is the thing you are touching.

One source for each concept

The Controls panel, the Patch Bay and the node editor read the same tokens. A new component is added to a shared selector list, never restyled on its own.

Every control has four states

Rest, hover, pressed and keyboard focus. If you can click it, it answers the pointer; if you can tab to it, it shows a ring.

Nothing native shows through

Dropdowns, scrollbars, spin buttons, cursors: anything the browser would draw in its own style is replaced.

Colour

Three surface tiers stack from the darkest bar to the lightest card. Click a swatch to copy its value.

Controls and their states

Hover the live ones. The states below use the same rules as the app.

Disclosure caret

Collapses and expands a group in Controls and a node in the Patch Bay. Rest is a dim grey chevron; hover washes the square green and lights the chevron; pressed deepens the wash and shrinks it slightly; keyboard focus draws the ring. It points down when open and right when closed.

Child groups

A group inside a Controls section is a recessed well. Hovering it lifts the well and lights its title; an open group carries a green rule on its left edge; pressing the title deepens the wash; focus anywhere inside rings the group. Groups start collapsed every time the app loads.

Tooltips and the info panel

Hover anything for about half a second for a one-line tooltip. The ⓘ button on a section, module or node opens a panel with a plain-language summary, a live signal-flow diagram of how that unit is patched right now, and a reference row for every parameter. It closes with Esc, ✕ or a click outside.

Motion

Everything that opens or closes (a section, a child group, a Patch Bay node) moves with second-order motion: a spring, not a fixed curve. A spring has position and velocity, so a thing accelerates out of rest, arrives with the speed it built up and carries that speed over if you reverse it mid-flight. Two springs run together:

▶ Play the springs

  • Fast · 120ms — hover colour and background changes (not springs).
  • Springs — expand and collapse: ω 26 rad/s for height, ω 22 with ζ 0.55 for the caret and fade. The container clips while it moves; its content fades in a beat after the box opens.
  • Press shrinks a control to 97%; lift raises a hovered card 2px (never during a drag).
  • Reduced motion turns off lift, glow, ripple and springs; state is still shown with static colour.

Layout

The workspace is four windows: Controls on the left, the Renderer in the centre, the Patch Bay on the right and the Timeline along the bottom. Each window has a tab bar; any view can be added to any window, dragged between them, popped out to its own OS window, collapsed to its tab strip, or maximised. Moving a view never moves a different one.

  • Section and node headers are the disclosure points; a child group inside a section starts collapsed every time the app loads.
  • A collapsed Patch Bay node shows only its header and its sockets, like a node in Blender or TouchDesigner.
  • On a phone the interface becomes a camera: full-bleed picture, a capture dock and five sheets.
